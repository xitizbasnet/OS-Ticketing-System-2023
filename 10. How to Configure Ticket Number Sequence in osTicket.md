# How to Configure Ticket Number Sequence in osTicket

 ## 📋 Overview

 This document explains how to access the **osTicket** administrator settings and configure the system-wide default ticket settings and options.

 After completing this configuration, newly created tickets will use the configured ticket-number sequence and start from **#1**, rather than receiving a random ticket number.

---

 ## 🔐 1. Open the osTicket Settings Page

 Open the **Chrome** browser and go to the following URL:

```
localhost/osTicket/scp/settings.php
```

---

 ## 🔑 2. Log In With Administrator Credentials

 Enter the administrator credentials:

 | Field | Value |
| --- | --- |
| **Username** | `itsupport@osticket.com` |
| **Password** | `password@123` |

Click **Login**.

 > ⚠️ **Warning:** Do not store production administrator credentials in GitHub repositories, documentation files, or other publicly accessible locations. Use a secure credential-management solution instead.

---

 ## ⚙️ 3. Open Ticket Settings

 After logging in:

 1. Go to the menu option called **Settings**.
2. Under **Settings**, select **Tickets**.

 The **Tickets** settings page contains:

 > **System-wide default ticket settings and options.**

---

 ## 🎫 4. Configure Default Ticket Settings

 Configure the ticket settings as follows.

 ### Ticket Number Settings

 | Setting | Configuration |
| --- | --- |
| **Default Ticket Number Format** | `#` |
| **Example** | `1` |
| **Default Ticket Number Sequence** | `Tasks Sequence` |
| **Top-Level Ticket Counts** | **Enable** |

The configured ticket number format is:

```
#
```

 Example:

```
1
```

---

 ### 📌 Default Ticket Options

 Configure the following default ticket options:

 | Setting | Value |
| --- | --- |
| **Default Status** | `Open` |
| **Default Priority** | `Normal` |
| **Default SLA** | `Default SLA (18 hours - Active)` |
| **Default Help Topic** | `— None —` |
| **Lock Semantics** | `Lock on activity` |
| **Default Ticket Queue** | `Open` |
| **Maximum Open Tickets** | `0` |

For **Maximum Open Tickets**, the setting applies:

```
per end user
```

 Enter a valid numeric value.

---

 ## 🛡️ 5. Configure Human Verification

 Under **Human Verification**, configure the option as follows:

```
☐ Enable CAPTCHA on new web tickets.
```

 The option should remain **disabled** unless CAPTCHA is required by your organization's ticketing policy.

---

 ## 👥 6. Configure Collaborator Tickets Visibility

 Under **Collaborator Tickets Visibility**, configure:

```
☑ Enable
```

 This enables collaborator ticket visibility.

---

 ## 📤 7. Configure Claim on Response

 Under **Claim on Response**, configure:

```
☑ Enable
```

---

 ## 🔄 8. Configure Auto-Refer on Close

 Under **Auto-refer on Close**, configure:

```
☑ Enable
```

---

 ## 🔒 9. Configure Ticket Closing Options

 Configure the following options:

 ### Require Help Topic to Close

```
☐ Enable
```

 ### Allow External Images

```
☐ Enable
```

 Both options should remain **disabled** according to the provided configuration.

---

 ## 📎 10. Configure Attachments

 Under **Attachments**, the following information is displayed:

 > **Size and maximum uploads setting mainly apply to web tickets.**

 The **Ticket Attachment Settings** option is:

```
Config
```

 Review the attachment configuration according to your organization's requirements.

---

 ## 💾 11. Save the Changes

 After configuring the ticket settings:

 1. Review the settings to make sure they match the required configuration.
2. Click the **Save Changes** button.

 After the changes are successfully saved, the following success alert message is displayed:

```
sucessfully updated ticket settings and options
```

 > ✅ **Success:** The system-wide ticket settings and options have been successfully updated.

---

 ## 🔢 12. Verify the Ticket Number Sequence

 After the ticket-number configuration has been saved, when a user raises a new ticket, the ticket numbering will start from:

```
#1
```

 Instead of assigning a random ticket number.

 ### Example

 The first ticket will be:

```
#1
```

 The next tickets will follow the configured **Tasks Sequence**.

 > 💡 **Tip:** After changing ticket-number settings, create a test ticket to verify that the numbering behavior matches the expected sequence.

 ## ✅ Best Practices

 - Verify all ticket settings before clicking **Save Changes**.
- Test the ticket-number sequence after making configuration changes.
- Use a test ticket rather than modifying a production ticket when validating configuration.
- Document any organization-specific changes to the default settings.
- 🔐 Never commit administrator passwords to GitHub.
- Use unique, strong administrator credentials and an approved secrets-management solution.
- Review ticket-number configuration before deploying changes to a production osTicket environment.

 The first ticket will start at:

```
#1
```

 rather than being assigned a random number.
