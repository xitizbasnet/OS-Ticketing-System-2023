# How to Delete the osTicket Database in XAMPP

 ## 📋 Overview

 This document explains how to delete the **osTicket** database from a XAMPP environment using **phpMyAdmin**.

 The procedure also explains how to verify the deletion by accessing the osTicket web application afterward.

 > ⚠️ **Warning:** Deleting a database is a **destructive operation**. All data stored in the selected database will be removed. Make sure you have a verified database backup before proceeding.

---

 ## ⚠️ Before You Begin

 Before deleting the database:

 - Verify that the database you are deleting is the correct database.
- Confirm that the database name is `osticket`.
- Ensure that a recent database backup is available if the data may be needed later.
- Do not perform this procedure on a production system unless the deletion has been properly authorized.

 > 💡 **Best Practice:** Always take and verify a backup before deleting an important database.

---

 ## 🌐 1. Open phpMyAdmin

 Open **Google Chrome** and go to the following URL:

```
localhost/phpmyadmin
```

 The **phpMyAdmin** dashboard will open.

---

 ## 🗄️ 2. Open the Databases Menu

 Locate the database named:

```
osticket
```

 On the top menu, you can see the menu option:

```
Databases
```

 Click **Databases**.

---

 ## ☑️ 3. Select the osTicket Database

 On the **Databases** page, locate:

```
osticket
```

 Tick the checkbox next to the **osticket** database.

---

 ## 🗑️ 4. Select the Drop Option

 After selecting the `osticket` database, locate the **Drop** menu option at the top of the databases section.

 Click:

 **Drop**

 > ⚠️ **Warning:** The **Drop** operation permanently removes the selected database and its tables. Verify the database name carefully before continuing.

---

 ## ⚠️ 5. Confirm Database Deletion

 phpMyAdmin will ask for confirmation to delete the database.

 To proceed, click:

 **Drop**

 The database deletion will then be performed.

---

 ## ✅ 6. Verify the Database Was Deleted

 After the database has been successfully deleted, phpMyAdmin displays the following success alert message:

```
1 database has been dropped sucessfully.
```

 > ✅ **Success:** The `osticket` database has been successfully deleted from the XAMPP database server.

---

 ## 🌐 7. Verify the osTicket Web Application

 After successfully deleting the database, open the browser and go to:

```
localhost/osTicket/index.php
```

 Because the osTicket application can no longer access its database, the dashboard displays:

```
HTTP ERROR 500
```

---

 ## 🔍 8. Verify the Result

 The **HTTP ERROR 500** message indicates that the osTicket web application is no longer functioning correctly after the database was deleted.

 In this procedure, this behavior is used as an additional verification that the database deletion has affected the osTicket application.

 > 📝 **Note:** An HTTP 500 error does not, by itself, prove that a database was deleted. For reliable verification, confirm that the `osticket` database is no longer listed in phpMyAdmin.

 ## 🛡️ Best Practices

 - 🔴 **Always verify the database name** before selecting **Drop**.
- 💾 **Create a backup** before deleting the database.
- 🔐 Store database backups securely because they may contain sensitive osTicket information.
- 🧪 If this is a test environment, clearly identify it before performing destructive operations.
- 📋 Obtain appropriate authorization before deleting a production database.
- 🔎 Verify the deletion directly through phpMyAdmin rather than relying only on the web application's error message.
- ♻️ If the database needs to be recovered, use a verified SQL backup to restore the database.
