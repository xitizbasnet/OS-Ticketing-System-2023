# Configure Knowledge Base Settings in osTicket

 This guide explains how to enable the **Knowledge Base**, require clients to log in before accessing it, and enable **Canned Responses** in osTicket.

 >  **Application:** osTicket\
>  **Configuration Area:** Staff Control Panel → Settings → Knowledge Base

---

 ## 🎯 Objective

 Configure the osTicket Knowledge Base with the following settings:

 - Enable the **Knowledge Base**.
- Require clients to **log in** to access the Knowledge Base.
- Enable **Canned Responses**.

 ### Final Configuration

 | Setting | Configuration |
| --- | --- |
| **Knowledge Base Status** | ☑ Enable Knowledge Base |
| **Client Access** | ☑ Require Client Login |
| **Canned Responses** | ☑ Enable Canned Responses |

> **Note:** Disabling the Knowledge Base disables the client-facing Knowledge Base interface.

---

 # Step 1: Open the osTicket Settings

 1. Open **Google Chrome**.
2. Navigate to:

```
localhost/osTicket/scp/settings.php
```

 3. Sign in with an administrator account if prompted.
4. Go to **Settings**.

---

 # Step 2: Open Knowledge Base Settings

 1. Under **Settings**, locate **Knowledge Base**.
2. Open the **Knowledge Base** configuration page.
3. Locate the **Knowledge Base Settings and Options** section.

 The page should display the following notice:

 > **Disabling knowledge base disables clients' interface.**

---

 # Step 3: Configure Knowledge Base Settings

 Under **Knowledge Base Status**, enable the following options:

```
☑ Enable Knowledge Base
☑ Require Client Login
```

 ### Configuration Details

 | Option | Status |
| --- | --- |
| **Enable Knowledge Base** | ☑ Enabled |
| **Require Client Login** | ☑ Enabled |

This configuration enables the Knowledge Base while requiring clients to authenticate before accessing it.

---

 # Step 4: Enable Canned Responses

 Under **Canned Responses**, enable:

```
☑ Enable Canned Responses
```

 ### Configuration

 | Option | Status |
| --- | --- |
| **Enable Canned Responses** | ☑ Enabled |

Canned Responses can be used by support staff to provide standardized responses to common ticket requests.

---

 # Step 5: Save the Changes

 After completing the configuration:

 1. Review all settings.
2. Confirm that the required checkboxes are enabled.
3. Click **Save Changes**.
4. Verify that the settings are saved successfully.

---

 # ✅ Final Configuration Checklist

 Use the following configuration as a reference:

```
Knowledge Base Settings and Options

Disabling knowledge base disables clients' interface.

Knowledge Base Status:

☑ Enable Knowledge Base
☑ Require Client Login

Canned Responses:

☑ Enable Canned Responses

[Save Changes]
```

---

 ## 🔎 Expected Result

 After saving the configuration:

 - The **Knowledge Base** is enabled.
- Clients are required to **log in** to access the Knowledge Base.
- **Canned Responses** are enabled for support staff.

---

 ## 💡 Best Practices

 - **Require authentication:** Requiring client login provides controlled access to Knowledge Base content.
- **Keep articles current:** Regularly review and update Knowledge Base articles.
- **Use Canned Responses consistently:** Create standardized responses for frequently occurring support requests.
- **Test after saving:** Verify that the Knowledge Base and Canned Responses are available as expected.
- **Review access requirements:** Ensure the login requirement aligns with your organization's customer-access policy.

 > **⚠️ Warning:** Disabling the Knowledge Base disables the client-facing Knowledge Base interface. Verify the **Enable Knowledge Base** option before saving changes in a production environment.

 > **💡 Tip:** After saving, test the Knowledge Base using a client account to confirm that the login requirement is working as intended.
