# Configure Alerts and Notifications in osTicket

 This guide explains how to configure **Alerts and Notices** in osTicket. These settings determine which staff members receive notifications for new tickets, new messages, internal activity, ticket assignments, ticket transfers, overdue tickets, and system-level errors.

>  **Application:** osTicket\
>  **Configuration Area:** Staff Control Panel → Settings → Tickets → Alerts and Notices

---

 ## Prerequisites

 Before you begin, make sure you have:

 - Administrator access to the osTicket Staff Control Panel.
- Permission to modify ticket and notification settings.
- Access to the osTicket installation through a web browser.

---

 ## Step 1: Open the osTicket Settings Page

 1. Open **Google Chrome**.
2. Navigate to the following URL:

```
localhost/osTicket/scp/setting.php
```

 3. Sign in with an administrator account if prompted.

---

 ## Step 2: Open Ticket Settings

 From the osTicket Staff Control Panel:

 1. Go to **Settings**.
2. Select **Tickets**.
3. Open the **Alerts and Notices** menu.

 The Ticket Settings and Options page contains the following configuration areas:

 - **Settings**
- **Autoresponder**
- **Alerts and Notices**
- **Queues**

 Select **Alerts and Notices** to begin the configuration.

---

 # Step 3: Configure Ticket Alerts

 Configure the following alert settings according to your organization's notification requirements.

 ## 🆕 New Ticket Alert

 Set the status to:

 > **Status: Enable**

 Configure the recipients as follows:

 - ☐ **Admin Email** (`amjid@syncbricks.com`)
- ☐ **Department Manager**
- ☑ **Department Members**
- ☐ **Organization Account Manager**

 ### Configuration

 | Recipient | Status |
| --- | --- |
| Admin Email (`amjid@syncbricks.com`) | ☐ Disabled |
| Department Manager | ☐ Disabled |
| Department Members | ☑ Enabled |
| Organization Account Manager | ☐ Disabled |

---

 # Step 4: Configure System Alerts

 Locate the **System Alerts** section.

 Configure the following options:

 - ☐ **System Errors** — enabled by default
- ☑ **SQL errors**
- ☑ **Excessive failed login attempts**

 ### Configuration Summary

 | System Alert | Status |
| --- | --- |
| System Errors | ☐ |
| SQL errors | ☑ |
| Excessive failed login attempts | ☑ |

> ⚠️ **Security Note:** Keeping notifications for **SQL errors** and **excessive failed login attempts** enabled can help administrators identify application and security-related issues.

---

 # Step 5: Save the Configuration

 After completing the configuration:

 1. Review each alert section.
2. Confirm that the **Enable/Disable** status is correct.
3. Verify the selected recipients.
4. Verify the **System Alerts** settings.
5. Click **Save**.

 The configured alerts and notifications will then be saved.

 ## 💡 Best Practices

 - **Test notifications:** Create test tickets and perform assignment/transfer actions to verify the expected alerts.
- **Avoid notification overload:** Only notify roles that need to take action.
- **Monitor security alerts:** Keep **SQL errors** and **excessive failed login attempts** enabled where appropriate.
- **Review disabled alerts:** Periodically verify that disabled alerts are intentionally disabled and not preventing important operational notifications.
- **Document changes:** Record production configuration changes according to your organization's change-management process.

 > **Tip:** If an expected alert is not received, first verify that the alert's **Status** is enabled, then check the selected recipient, department/team assignment, and email configuration.
