 # 👤 How to Create and Register a Local User in osTicket

 This guide explains how to **create a user locally** in the osTicket administration portal and then **register the user account** for authentication.

 > \[!NOTE\]\
>  This procedure creates a **temporary local user**. In a professional production environment, users can also be created and managed through **Active Directory**, which is the recommended approach when centralized identity management is available.

---

 ## 🔐 1. Log In to the Admin Portal

 To create and register a user, first log in to the osTicket administration portal.

 ### Open the Admin Portal

 1. Open **Google Chrome**.
2. Enter the following URL:

```
localhost/osTicket/scp/login.php
```

 3. Enter the administrator credentials:

 | Field | Value |
| --- | --- |
| **Username** | `itsupport` |
| **Password** | `password@123` |

4. Click the **Login** button.

 > \[!TIP\]\
>  Use administrator credentials with sufficient permissions to manage users.

 You have now **successfully logged in to the admin portal**.

---

 ## 👥 2. Navigate to Users

 After successfully logging in:

 1. Go to **Users** from the menu bar.
2. The page will be redirected to:

```
localhost/osTicket/scp/users.php
```

 3. Click **Add Users**.

---

 ## 📝 3. Create a New User

 After clicking **Add Users**, a **New User** dashboard will appear.

 Fill in the necessary user information.

 ### User Information

 | Field | Value |
| --- | --- |
| **Email Address** | `dilip@osticket.com` |
| **Full Name** | `dilip karki` |
| **Phone Number** | `+977-9812345689` |
| **Ext** |  |
| **Internal Notes** | `audit team` |

4. Click **Add User**.

 > \[!NOTE\]\
>  The user has now been **created successfully**.

---

 ## ⚠️ Local User vs. Active Directory User

 > \[!WARNING\]\
>  This is a **temporary user created locally**. We can create users through **Active Directory** as well, which is the more professional approach for centralized user and authentication management.

 For the current procedure, we will use **local registration**.

---

 # 🔑 4. Register the Created User

 After creating the user, the page may move to a URL similar to:

```
localhost/osTicket/scp/users.php?id=3
```

 On this dashboard, you can view the user's information.

 You will also see a **Register** button.

 ### Register the User

 1. Locate the **Register** button on the user dashboard.
2. Click **Register**.

 > \[!NOTE\]\
>  For the current procedure, we will use **local registration**.

---

 ## ⚙️ 5. Configure the User Registration

 After clicking **Register**, the user registration dashboard will display the account information and authentication settings.

 Enter or configure the following values:

 | Setting | Value |
| --- | --- |
| **Authentication Sources** | Use any available backend |
| **Username** | `dilip@osticket.com` |
| **Status** | Untick **Send account activation email to dilip@osticket.com** |
| **Temporary Password** | `password@123` |
| **Confirm Password** | `password@123` |
| **Time Zone** | System Default |

### Account Activation Email

 For the current local setup, make sure the following option is **unticked**:

```
Send account activation email to dilip@osticket.com
```

 > \[!NOTE\]\
>  The activation email option is disabled in this procedure because this is a local/temporary user setup.

---

 ## ➕ 6. Create the Account

 After entering and reviewing all the required registration information:

 1. Click **Create Account**.

 The user has now been **registered successfully**.

---

 ## ✅ 7. Verify the User Registration

 To verify that the user has been registered:

 1. Navigate back to **Users**.
2. Open:

```
localhost/osTicket/scp/users.php
```

 3. Locate **dilip karki** in the user list.

 The user's status should now appear as:

```
Active (REGISTERED)
```

 This confirms that the user was successfully created and registered locally.

 ## 💡 Best Practices

 - Use **Active Directory** or another centralized identity provider for production environments when available.
- Avoid using simple or shared administrator passwords in production.
- Use a unique password for each user account.
- Verify the user's **email address, name, and contact information** before registration.
- Confirm that the user's status is **Active (REGISTERED)** after creating the account.
- Document temporary/local accounts and remove them when they are no longer required.
- Avoid exposing administrator credentials in documentation stored in a public GitHub repository.

 > \[!CAUTION\]\
>  The credentials shown in this procedure, such as `itsupport` / `password@123`, should be treated as **example or temporary credentials**. Do not use or publish real production credentials in documentation.
