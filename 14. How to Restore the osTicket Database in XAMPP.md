# How to Restore the osTicket Database in XAMPP

 ## 📋 Overview

 This document explains how to restore the **osTicket** database in a XAMPP environment using **phpMyAdmin**.

 The procedure covers:

 - Creating the `osticket` database.
- Importing the previously created `osticket.sql` backup.
- Troubleshooting the `#1050 - Table 'pma_bookmark' already exists` error.
- Verifying that the osTicket application is working after the restoration.

---

 ## ⚠️ Before You Begin

 Before starting the database restoration:

 - Ensure XAMPP and its database service are running.
- Make sure the `osticket.sql` backup file is available.
- Verify that the backup file is the correct backup for the osTicket installation.
- Keep the original backup file unchanged so it can be reused if the restore fails.

 > 💡 **Best Practice:** Always keep an original copy of the SQL backup before attempting a database restore.

---

 ## 🌐 1. Open phpMyAdmin

 Open **Google Chrome** and go to:

```
localhost/phpmyadmin
```

 The phpMyAdmin dashboard will open.

---

 ## 🗄️ 2. Open the Databases Menu

 Locate the database section.

 The database name used for osTicket is:

```
osticket
```

 On the top menu, locate:

 **Databases**

 Click **Databases**.

---

 ## ➕ 3. Create the osTicket Database

 Under **Create database**, fill in the following information:

 | Setting | Value |
| --- | --- |
| **Database Name** | `osticket` |
| **Collation** | `utf8mb4_general_ci` |

The configuration should be:

```
Database name: osticket
Collation: utf8mb4_general_ci
```

 Click the **Create** button.

---

 ## ✅ 4. Verify Database Creation

 After the database has been successfully created, a success alert message is displayed:

```
database osticket has been created.
```

 > ✅ **Success:** The `osticket` database has been created successfully.

 After creation, phpMyAdmin opens the new database dashboard and displays additional database options.

---

 ## 📥 5. Open the Import Option

 On the top menu bar, locate:

 **Import**

 Click **Import**.

---

 ## 📂 6. Select the SQL Backup File

 On the Import page:

 1. Click **Choose File**.
2. Navigate to the **Downloads** folder.
3. Select the previously created database backup:

```
osticket.sql
```

 The selected file will be used to restore the osTicket database.

---

 ## 📤 7. Import the Database

 After selecting the `osticket.sql` file:

 1. Scroll down to the end of the page.
2. Locate the **Import** button.
3. Click **Import**.

 phpMyAdmin will begin importing the SQL database backup.

 > ⏳ **Note:** The amount of time required depends on the size of the SQL backup.

---

 # 🛠️ Troubleshooting

 ## ⚠️ 8. Resolve the Existing Table Error

 Sometimes errors may occur during the database import.

 One possible error message is:

```
#1050 - Table 'pma_bookmark' already exists
```

 If this error occurs, follow the troubleshooting procedure below.

---

 ## 🔧 9. Select the osTicket Database

 Go to the database list on the left side of phpMyAdmin.

 Select:

```
osticket
```

 After selecting the `osticket` database, the database tables will be displayed.

---

 ## ☑️ 10. Select All Tables

 Scroll down to the bottom of the table list.

 Locate the option:

 **Check all**

 Tick the checkbox for:

 **Check all**

---

 ## 🔧 11. Select Repair Table

 On the right side of **Check all**, locate the drop-down menu.

 From the available options, choose:

 **Repair table**

 The final selection should be:

```
Check all > Repair table
```

 Wait for some time while the operation is performed.

---

 ## ✅ 12. Verify the Repair Operation

 After the operation has completed, the following success alert message may be displayed:

```
your SQL query has been executed successfully
```

 > ✅ **Success:** The SQL query has been executed successfully.

---

 # 🌐 Verify the osTicket Application

 ## 13\. Open osTicket

 After restoring the database, open **Google Chrome** and go to:

```
localhost/osticket
```

 The osTicket dashboard should now be displayed.

---

 ## 🔍 14. Verify the Restoration

 Verify that:

 - The osTicket dashboard loads successfully.
- The application can access the restored database.
- The expected osTicket data is available.
- No database connection errors are displayed.

 > ✅ **Success:** The osTicket database has been successfully restored and verified from the web browser.

 ## 💡 Best Practices

 - 💾 Always keep a copy of the original `osticket.sql` backup.
- 🔍 Verify the backup file before beginning the restoration.
- ⚠️ Do not overwrite or modify the original backup unnecessarily.
- 🧪 Test database restoration in a non-production environment when possible.
- 🔐 Treat SQL backups as sensitive data because they may contain user and ticket information.
- 📋 Document the date, source, and purpose of each database backup.
- ✅ After restoration, verify both the application and important ticket data.

 > ⚠️ **Important:** The `pma_bookmark` table is associated with phpMyAdmin's configuration storage. If the import reports existing-table conflicts, do not blindly repair or overwrite tables in a production environment. First determine whether the conflicting table belongs to the osTicket backup or phpMyAdmin configuration and use a clean, known-good database state where possible.
