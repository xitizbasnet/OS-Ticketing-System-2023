 # 🎫 How to Create a Ticket from the osTicket User Portal

 This guide explains how a registered user can log in to the **osTicket user portal** and create a new support ticket.

 The example below uses the user **Dilip** and creates a ticket for a **mouse not working** issue.

---

 ## 🌐 1\. Open the osTicket User Portal

 1. Open the **Google Chrome** browser.
2. Enter the following URL in the address bar:

```
localhost/osTicket/login.php
```

 3. Press **Enter**.

---

 ## 🔑 2. Sign In to the User Portal

 On the osTicket login page:

 1. Click the **Sign In** option at the **top-right corner**.
2. Enter the user credentials:

 | Field | Value |
| --- | --- |
| **Username** | `dilip@osticket.com` |
| **Password** | `password@123` |

3. Click the **Sign In** button.

 > \[!NOTE\]\
>  These are the credentials for the local user **Dilip** created and registered in the previous procedure.

---

 ## 👤 3. Access the User Dashboard

 After a successful login, the user's dashboard will be displayed under the name:

```
dilip
```

 From this dashboard, the user can view their **ticket details and information**.

---

 ## 🆕 4\. Open a New Ticket

 To create a new support ticket:

 1. Click the **Open a New Ticket** button.

 After clicking **Open a New Ticket**, the page will be redirected to:

```
localhost/osTicket/open.php
```

---

 ## 📝 5. Enter the Ticket Information

 On the **Open a New Ticket** page, provide the required ticket information.

 ### Help Topic

 Under **Help Topic**, choose:

```
General Inquiry
```

 ### Issue Summary

 Under **Issue Summary**, enter:

```
mouse is not working
```

---

 ## 🎫 6. Create the Ticket

 After entering the ticket information:

 1. Review the details.
2. Click the **Create Ticket** button to proceed.

 The ticket will then be submitted to the osTicket system.

---

 ## ✅ 7. Verify Ticket Submission

 The ticket has now been **successfully raised from the user Dilip**.

 The submitted ticket can be viewed from the user's dashboard under the ticket details/information.

 > \[!TIP\]\
>  When creating a ticket, provide a clear and concise issue summary. This helps the IT support team quickly understand the reported problem.

 ## 💡 Best Practices

 - Use a clear **Help Topic** that matches the reported issue.
- Keep the **Issue Summary** short and descriptive.
- Provide additional details when necessary to help L1/L2 engineers troubleshoot the issue.
- Review the ticket information before clicking **Create Ticket**.
- After submission, verify that the ticket appears in the user's dashboard.
- Never publish real production credentials in IT documentation or a public GitHub repository.

 > \[!CAUTION\]\
>  `password@123` is retained here because it was part of the provided procedure. Treat it as a **temporary/local example credential** and replace it with a secure password in any production environment.
