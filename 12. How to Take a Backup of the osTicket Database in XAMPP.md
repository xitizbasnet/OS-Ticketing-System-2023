# How to Take a Backup of the osTicket Database in XAMPP

 ## 📋 Overview

 This document explains how to take a backup of the **osTicket database** using **phpMyAdmin** in a XAMPP environment.

 The backup is exported as an SQL file and can be renamed for easier identification and future use.

---

 ## 🛠️ Prerequisites

 Before starting, ensure that:

 - XAMPP is installed.
- The XAMPP services required for phpMyAdmin are running.
- The osTicket database is available in MySQL/MariaDB.
- Google Chrome is available.

 > 💡 **Tip:** Before performing the backup, verify that the osTicket application and database are accessible.

---

 ## 🌐 1. Open phpMyAdmin

 Open **Google Chrome** and go to the following URL:

```
localhost/phpmyadmin
```

 The **phpMyAdmin** interface will open.

---

 ## 🗄️ 2. Locate the osTicket Database

 In phpMyAdmin, locate the database named:

```
osticket
```

 On the top menu, you can see the menu options, including:

```
Databases
```

 Click **Databases**.

---

 ## ☑️ 3. Select the osTicket Database

 On the **Databases** page, locate the database:

```
osticket
```

 Tick the checkbox next to **osticket**.

---

 ## 📤 4. Open the Export Option

 After selecting the **osticket** database, look at the menu options at the top of the menu bar.

 Locate:

```
Export
```

 Click **Export**.

 > 📝 **Note:** Wait for a moment while phpMyAdmin loads the export dashboard.

---

 ## 📦 5. Export the Database

 A new dashboard will appear.

 Look for the **Export** option/icon at the bottom of the page.

 Click:

 **Export**

 phpMyAdmin will export the selected **osticket** database.

 > ⏳ **Tip:** Depending on the size of the database, the download may take a few moments.

---

 ## 📁 6. Locate the Database Backup

 After the export has completed, go to the **Downloads** folder.

 You should see a file named:

```
127.0.0.1.sql
```

 This file contains the exported database backup.

---

 ## 🔄 7. Rename the Backup File

 For future necessity and easier identification, rename the database backup file:

```
127.0.0.1.sql
```

 to:

```
osticket.sql
```

 ### Before

```
127.0.0.1.sql
```

 ### After

```
osticket.sql
```

 > 💡 **Best Practice:** Use descriptive names for database backups so that the database and purpose of the backup can be identified easily.

---

 ## ✅ 8. Verify the Backup

 Verify that the renamed file exists in the Downloads folder:

```
osticket.sql
```

 The `.sql` file is the exported backup of the **osticket** database.

 > ✅ **Success:** The osTicket database has been successfully exported and backed up.

 ## ⚠️ Backup Best Practices

 - Keep database backups in a secure location.
- Do not store sensitive database backups in a public GitHub repository.
- Maintain multiple backup copies when the database is important.
- Use descriptive backup filenames.
- Periodically test that backups can be restored successfully.
- Consider including the backup date in production backup filenames, for example:

```
osticket-2026-09-15.sql
```

 - Protect backup files because they may contain sensitive ticket, user, and system information.
