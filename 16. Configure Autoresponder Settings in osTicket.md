# Configure Autoresponder Settings in osTicket

 This guide explains how to configure the **Autoresponder** settings in osTicket. These settings control which users receive automatic notifications when tickets or ticket messages are created, and when ticket limits are exceeded.

>  **Application:** osTicket\
>  **Configuration Area:** Staff Control Panel → Settings → Tickets

---

 ## Prerequisites

 Before you begin, ensure that:

 - You have administrator access to the osTicket Staff Control Panel.
- osTicket is installed and accessible through your local web server.
- You have permission to modify ticket and notification settings.

---

 ## Step 1: Open the osTicket Staff Control Panel

 1. Open **Google Chrome**.
2. Enter the following URL in the address bar:

```
localhost/osTicket/scp/setting.php
```

 3. Press **Enter**.
4. Sign in with an account that has the required administrative permissions, if prompted.

---

 ## Step 2: Open Ticket Settings

 1. From the osTicket Staff Control Panel, select:
    **Settings \> Tickets**
2. Locate the **Autoresponder** menu option.

 > **Note:** The global autoresponder configuration can be overridden or disabled at the **Department** or **Email** level.

---

 ## Step 3: Configure Autoresponder Options

 Configure each section according to the following settings.

 ### New Ticket

 For newly created tickets, enable notification to the ticket owner:

 - ☑ **Ticket Owner**

 ### New Ticket by Agent

 For tickets created by an agent, enable notification to the ticket owner:

 - ☑ **Ticket Owner**

 ### New Message

 Configure notifications generated when a new message is added to a ticket:

 - ☐ **Submitter: Send receipt confirmation**
- ☑ **Participants: Send new activity notice**

 This configuration prevents the submitter from receiving a receipt confirmation while allowing participants to receive notifications about new ticket activity.

 ### Overlimit Notice

 Enable notification to the ticket submitter when the ticket exceeds the applicable limit:

 - ☑ **Ticket Submitter**

---

 ## Configuration Summary

 Use the following configuration as the final reference:

 | Setting | Configuration |
| --- | --- |
| **Global Setting** | Can be disabled at the department or email level |
| **New Ticket** | ☑ Ticket Owner |
| **New Ticket by Agent** | ☑ Ticket Owner |
| **New Message — Submitter** | ☐ Send receipt confirmation |
| **New Message — Participants** | ☑ Send new activity notice |
| **Overlimit Notice** | ☑ Ticket Submitter |

---

 ## Step 4: Save the Configuration

 After verifying all settings:

 1. Review the **Autoresponder** configuration.
2. Confirm that the checkboxes match the configuration above.
3. Click **Save**.

 The updated autoresponder configuration will be applied to the ticketing system.

 ## 💡 Best Practices

 - **Test after configuration:** Create a test ticket and verify that the expected notifications are received.
- **Check department-level settings:** If notifications do not behave as expected, verify whether the department has overridden the global configuration.
- **Check email-level settings:** Review the associated email configuration if autoresponder behavior differs from the global setting.
- **Document production changes:** Record configuration changes according to your organization's IT change-management process.
- **Avoid unnecessary notifications:** Configure notifications carefully to prevent excessive or duplicate emails for users and support staff.

 > ⚠️ **Warning:** Changes to autoresponder settings can affect customer and internal notification workflows. Always validate the configuration with a test ticket before making changes in a production environment.

 > **Tip:** If a user does not receive an expected notification, check the **Global**, **Department**, and **Email** settings first, as lower-level configurations may override the global autoresponder behavior.
